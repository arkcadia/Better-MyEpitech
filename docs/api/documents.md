# Document sources and coverage

These are **source-derived candidate adapters**, not a claim of complete authenticated portal coverage. The source evidence is the public frontend API inventory recovered on 22 October 2026. No school code, student materials or private responses are embedded in the application.

| Source | Discovery and file resolution | Current boundary |
| --- | --- | --- |
| Own personal documents, including administrative files | `GET /students/documents`, then `GET /students/documents/{id}/download` | Validate matching own login and visibility. The download response has a fresh URL; metadata provides filename, optional size/MIME and update time. |
| Accessible project resources | Paginated `GET /units/instances/projects` for accessible school years, then `/units/instances/projects/{id}/related-resources/files` | Recurse the returned storage tree, including nested `childrens`. Resolve only discovered file paths. |
| Historical units and activity resources | `GET /units/instances/school-years`, paginated `/units/instances?schoolYear=…&expanded=true`; permitted unit detail if expansion is absent | Use discovered unit year/code/instance/activity IDs with `/units/{year}/{unit}/{instance}/activities/{id}/files/students`. Missing expansion and ignored pagination are reported as incomplete. |
| Project-template briefs | Discovered unit template year and project-template ID, then `/units/{templateYear}/{unit}/projects/{templateId}/files/students` | Attempt only when the required context is present in accessible unit responses. Student scope only; no staff template browsing or ID guessing. Related-resource and template trees may expose the same underlying content under distinct source records. |
| E-learning PDFs | `/e-learning/overview`, each discovered `/e-learning/modules/{id}`, then `/e-learning/chapters/{id}/url` on download | PDFs marked downloadable become documents; streaming video URLs are not treated as original-file downloads. |
| E-learning chapter text and subtitles | `/e-learning/chapters/{id}/content` and `/subtitles` | Export accessible text as Markdown and declared subtitle languages as VTT. They have no reliable version marker in the recovered contract, so saved IDs are labeled version unknown; use an explicit all-selected export to refresh them. |
| Own follow-up attachments | `/students/follow-ups`, then discovered `/students/follow-ups/{id}/attachment` | Verified student login/visibility; binary response through the account-bound session reader. |
| External platforms, repository links and streaming media | Preserve school source context and show coverage notices | Link-only. Separate authenticated platforms and undocumented sources require additional connectors/validation; their contents are not silently claimed as ZIP files. |

File-route configuration is grounded in the generic Files source helpers and their public frontend call sites: project related resources, activity instance resources, and template project resources. The trees expose node IDs, names, kind, timestamps, optional MIME/blob ID and children. File resolution returns a signed URL (the generic client navigates to the returned string). No folder-create, upload, rename, delete, registration, attendance or staff-storage operation is performed.

Collectors traverse all returned historical years/pages/folders without applying a current-term/registered-only filter. Safety caps are visible: 5,000 read requests per scan, 100 years, 100 pages per source query, 20,000 discovered documents, 20,000 tree nodes per tree and depth 40. A malformed/forbidden/failed source, missing folder expansion, mismatched page count, ignored page parameter or cap produces a coverage gap. A successful endpoint response is labeled **collected**, not **validated against the portal**. Collection is a manual fresh scan; it does not delete existing device copies or infer remote deletions from missing/partial results.

Signed URLs are resolved only when a student requests a ZIP. Expected HTTPS file hosts must be configured exactly; default school API origin alone does not authorize an unknown storage host. The storage transfer omits cookies/bearers, rejects redirects, checks known byte sizes, streams bounded chunks and retries a rejected expiring link once by resolving a new URL. API authentication/refresh stays inside the school session manager.

## Required live reconciliation

For a consenting real account, compare personal files, every accessible school year/unit/activity/project, nested folders, e-learning PDFs/text/subtitles and follow-up attachments with the portal. Record counts/gaps without committing names, signed URLs, credentials or private files. Verify server pagination and inherited/template resource behavior. Check file-host CORS and original bytes independently on web and Android. Only after this reconciliation can the project claim retrieval of **all** documents the student can access. This milestone preserves that goal while clearly exposing its current evidence limits.
